# TabLink 0.7.0 使用说明

电脑端与安卓客户端为 0.7.0 开发版。Windows 需要 .NET 10 Desktop Runtime 和 ASP.NET Core 10 Runtime。本版视频主路径使用 NVIDIA NVENC，需要兼容的 NVIDIA 编码器；不能承诺所有电脑和所有接收设备通用。

## 接收设备

| 平台 / 方式 | 本次提供 | 验证边界 |
|---|---|---|
| 安卓手机 / 平板 | android/TabLink.apk，Android 6.0+ | 已有中兴 W202DS 单设备实机记录；其他型号需测 H.264 / 屏幕模式 |
| 可安装 APK 的鸿蒙 | 可使用安卓 APK 的平台路径 | 需具体型号测试，不代表 HarmonyOS NEXT |
| iPhone / iPad 原生 | native/apple Swift 原生工程 | 需 Mac / Xcode 构建、签名、安装和实机验证；本包无 IPA |
| HarmonyOS NEXT 原生 | native/harmony 原生工程 | 需 DevEco / SDK 构建、签名、安装和实机验证；本包无 HAP |
| 浏览器 | 本地 HTTPS / WebRTC 接入页面 | 720p / 1080p、30 / 60 帧，先检测浏览器能力；不能把回环测试当作各型号 Safari / 鸿蒙浏览器验证 |

屏幕刷新率、解码完成、提交渲染和真正呈现是不同指标。HarmonyOS 原生路径使用独立的 render-submitted 进度，不计入实际呈现帧数。0.4.2 / 0.6.0 的历史 90 fps 记录不证明本版多屏同时达到 90 fps。

## 排除列表与内置 ADB

排除规则可以在连接期间添加、删除并保存，按序列号或精确 VID/PID 匹配。默认保留 F50 Pro 的序列号及两个 VID/PID 规则，没有排除整个中兴厂商。

命中规则的 USB 网络连接会先停止，再保存规则。ADB 兼容会话的授权绑定整份策略，因此规则变更时该会话需停止后重新批准。USB 排除规则无法识别 Wi-Fi 对端的硬件序列号；浏览器也不能读取 USB VID/PID。

随包工具位于 tools/platform-tools，固定 Google Platform-Tools 37.0.0，附来源、哈希和完整 NOTICE。定位顺序为有效显式路径、完整随包三件套、SDK、PATH；无效显式路径会报错，便于诊断修复。

## 检测与修复

在“检测与修复”点击“检测连接”，检查配置、ADB 文件哈希与执行、USB 设备授权、排除策略、网络线路、虚拟屏目标、FFmpeg、APK、冲突进程和当前连接进度。

- “修复：使用内置 ADB”将配置指向校验通过的随包工具。它不重启共享 ADB 服务。
- “修复：重建选中连接”重连多设备页所选原生设备，或当前主连接；ADB 连接会先清理本次反向映射，再重新批准并连接。
- 新设备提示缺少显示模式时，先让它扫码以报告参数，点击“读取设备请求模式”；停止所有设备，再“配置选中显示模式”，随后重新扫码。参数来自设备报告，不手工猜测。
- 设备未授权需在设备上允许；未开 USB 网络共享需在系统设置打开；修复按钮不能代替这些系统操作。苹果和 HarmonyOS NEXT 不使用 ADB。

检测不重置 USB、不重新绑定其他设备驱动、不关闭 UAC。驱动配置仅在所有连接停止后对精确验证的虚拟适配器执行。

## 多设备独立副屏

1. 保存副屏工作，在“多设备”页停止所有设备。选择 1–8 块可用副屏并配置。重新加载驱动后会收回全部空闲目标。
2. 第一台可使用首页的“开始配对”；其他原生设备点击“添加原生客户端连接”，分别扫描自己的二维码。
3. 浏览器设备在“浏览器”页分别生成新的单次二维码。原生与浏览器共用显示目标池，总活动目标不能超过配置数。
4. 停止选中设备只回收它自己的屏；“停止所有设备”和托盘“停止连接”会结束全部会话。点窗口 × 仍继续后台传输。

每个设备独立持有显示身份、H.264 编码、输入、连接健康与回收保护。多屏会增加 GPU、编码器和带宽负载；签名 VDD 25.7.23 的多输出性能需实测。代码隔离及合成传输通过，不等于三台真实设备同时通过。

## 本地离线浏览器与证书

1. 在“Wi-Fi / USB 免调试”选择线路，然后在“浏览器”开启接入。
2. 导出本机公开 CA 证书，传到自己的接收设备安装并信任，核对电脑显示的 SHA-256 指纹。私钥用当前 Windows 用户 DPAPI 加密保存，不随包导出，也不自动安装进系统信任库。
3. iPhone / iPad 手动安装证书描述文件后，还需在“设置 → 通用 → 关于本机 → 证书信任设置”启用该根证书的完全信任。其他系统按其证书设置操作。依据：[Apple 手动证书信任说明](https://support.apple.com/en-us/102390)。
4. 扫码，选择横竖屏、720p / 1080p 与 30 / 60 帧，点击开始。页面检测 WebRTC / H.264 和实际视频帧回调；能力不足会说明原因。
5. 二维码五分钟过期、只用一次。每台设备生成自己的二维码；断开后重新配对。切到后台、休眠或长期无视频进度可能导致副屏回收。

原生网络端口为 TCP 27184、27186–27192；ADB 兼容端口只绑定回环 TCP 27183。浏览器使用 HTTPS / WSS TCP 27185；每会话独占一个 UDP 偶数端口，从 27200、27202、27204、27206、27208、27210、27212、27214 中分配（RTCP 共用同一端口）。规则限制为本次程序、选择的网卡、本地 IP 和同一子网，结束时清理自己的规则。不使用公网 STUN / TURN 或云端中转。

USB 免开发者模式依赖设备提供 USB 网络共享 / 个人热点。安卓能力因型号而异；苹果需要其个人热点及 Windows 正常驱动。不能承诺任意设备插线即连，应用不会擅自切换 USB 配件模式或设置路由 / DNS。

## 原生平台构建限制

Apple 工程必须在有对应平台支持的 Mac / Xcode 中构建，真机安装需签名与预配。普通开发安装还可能要求设备开发者模式；用户希望免开发者模式的分发方式需要正常发行签名 / 发布流程，不可由 Windows 程序绕过。[Apple 真机运行文档](https://developer.apple.com/documentation/xcode/running-your-app-on-simulated-or-physical-devices)

HarmonyOS NEXT 工程同样需要官方 SDK、签名与真实设备测试。请阅读各 native 子目录的 README，明确源代码已完成范围、API 要求和待验证项。

## 更新和校验

以发行目录 SHA256SUMS.txt 与 VERIFICATION-0.7.0.md 为准。请保留旧版目录；切换 Windows 版本前停止所有设备并退出旧程序，运行新目录 TabLink.exe 接受管理员提示，再在设备重新扫码。Android 多端口连接需更新随包 0.7.0 APK。
